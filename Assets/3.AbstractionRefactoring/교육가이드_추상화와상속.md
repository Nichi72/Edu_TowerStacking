# 교육 가이드: 추상화와 상속

## 🎓 강의 흐름 제안

### 1단계: 문제 제기 (0.Origin 코드 보여주기)

**질문**: "새로운 블록 타입을 추가하려면 어디를 수정해야 할까요?"

```csharp
// Block.cs의 문제점
public enum BlockType { Normal, Golden, Big, Fast }

void ApplyBlockType()
{
    switch (blockType)
    {
        case BlockType.Golden:
            GetComponent<Renderer>().material.color = Color.yellow;
            break;
        case BlockType.Big:
            transform.localScale *= 1.5f;
            break;
        // 새 타입 추가하려면 여기도...
    }
}

void OnCollisionEnter()
{
    if(blockType == BlockType.Golden)
    {
        point = 2;
    }
    // 그리고 여기도 수정해야 함...
}
```

**문제점:**
- ❌ 여러 곳을 수정해야 함
- ❌ 실수하기 쉬움 (한 곳을 빠뜨리면 버그)
- ❌ 코드가 길어지고 복잡해짐

### 2단계: 객체지향 시도 (1.Refactoring 코드 보여주기)

**시도**: "타입별로 클래스를 분리하면 어떨까?"

```csharp
// GoldenBlock.cs
public class GoldenBlock : MonoBehaviour
{
    public float speed = 1f;
    public float range = 1f;
    // ... (전체 코드 복사)
    
    void Move() { /* 복사 */ }

// BigBlock.cs
public class BigBlock : MonoBehaviour
{
    public float speed = 1f;
    public float range = 1f;
    // ... (또 복사)
```

**문제점:**
- ❌ 코드 중복이 너무 많음
- ❌ Move() 로직을 수정하려면 모든 클래스를 수정해야 함
- ❌ 유지보수가 어려움

### 3단계: 해결책 - 추상화와 상속 (3.AbstractionRefactoring)

**핵심 아이디어:**
> "공통 기능은 한 곳에 모으고, 차이점만 각 클래스에 구현하자!"

#### 추상 클래스 설계

```csharp
// BaseBlock.cs - 추상 클래스
public abstract class BaseBlock : MonoBehaviour
{
    // ✅ 공통 변수
    public float speed = 1f;
    public float range = 1f;
    // ...
    
    // ✅ 공통 기능 - 여기 한 번만 작성!
    protected virtual void Move()
    {
        float x = Mathf.Sin(Time.time * speed) * range;
        transform.position = new Vector3(x + startX, transform.position.y, transform.position.z);
    }
    
    public virtual void Drop()
    {
        rb.isKinematic = false;
        col.enabled = true;
        isDrop = true;
    }
    
    // ❗ 블록마다 다른 부분은 추상 메서드로
    protected abstract void Initialize();  // 각 블록이 구현해야 함
    public abstract int GetScore();        // 각 블록이 구현해야 함
}
```

#### 구체 클래스 구현

```csharp
// GoldenBlock.cs - 차이점만 구현!
public class GoldenBlock : BaseBlock
{
    protected override void Initialize()
    {
        // 황금색으로 변경
        GetComponent<Renderer>().material.color = Color.yellow;
    }
    
    public override int GetScore()
    {
        return 2;  // 2점
    }
    
    // Move(), Drop() 등은 자동으로 상속됨!
}
```

```csharp
// BigBlock.cs - 이것도 간단!
public class BigBlock : BaseBlock
{
    protected override void Initialize()
    {
        // 크기만 변경
        transform.localScale *= 1.5f;
    }
    
    public override int GetScore()
    {
        return 1;  // 1점
    }
}
```

## 🔑 핵심 개념 설명

### 1. 추상 클래스 (Abstract Class)

**비유**: 건축 설계도면

```csharp
public abstract class BaseBlock  // "블록" 설계도
{
    // 모든 블록은 이동한다 (구현됨)
    void Move() { ... }
    
    // 모든 블록은 초기화된다 (어떻게? 각자 다름 → 추상)
    abstract void Initialize();
}
```

**특징:**
- `new BaseBlock()` ❌ 불가능 (설계도는 직접 못 지음)
- 자식 클래스에서 구체화 필요
- 공통 기능 + 강제 규격 제공

### 2. 상속 (Inheritance)

**비유**: 부모의 재산 물려받기

```csharp
public class GoldenBlock : BaseBlock  // BaseBlock을 상속
{
    // Move()는 자동으로 있음 (상속받음)
    // Initialize()는 반드시 구현해야 함 (추상 메서드)
}
```

**장점:**
- ✅ 코드 재사용
- ✅ 일관성 유지
- ✅ 유지보수 용이

### 3. 다형성 (Polymorphism)

**비유**: 같은 명령, 다른 결과

```csharp
BaseBlock block1 = new NormalBlock();
BaseBlock block2 = new GoldenBlock();
BaseBlock block3 = new BigBlock();

// 모두 같은 메서드 호출
block1.GetScore();  // 1 반환
block2.GetScore();  // 2 반환
block3.GetScore();  // 1 반환

// 하나의 배열로 모두 관리 가능!
BaseBlock[] blocks = { block1, block2, block3 };
foreach (var block in blocks)
{
    Debug.Log(block.GetScore());  // 각자 다른 점수
}
```

## 💬 학생들과의 대화 예시

### Q1: "추상 클래스와 일반 클래스의 차이는?"

**A:** 
- **일반 클래스**: 완성된 설계도 → 바로 만들 수 있음
- **추상 클래스**: 미완성 설계도 → 완성하고 만들어야 함

```csharp
// 일반 클래스
public class Car { }
Car myCar = new Car();  // ✅ OK

// 추상 클래스
public abstract class Vehicle { }
Vehicle myVehicle = new Vehicle();  // ❌ 에러!

// 상속받아서 완성
public class Car : Vehicle { }
Car myCar = new Car();  // ✅ OK
```

### Q2: "왜 굳이 추상 클래스를 사용하나요?"

**A:** 
1. **강제성**: "이 메서드는 반드시 구현하세요!"
2. **일관성**: 모든 블록이 GetScore()를 가지도록 보장
3. **설계**: 나중에 누가 봐도 어떻게 확장할지 명확

### Q3: "virtual과 abstract의 차이는?"

**A:**

```csharp
public abstract class BaseBlock
{
    // virtual: 구현이 있음, 오버라이드 선택적
    protected virtual void Move()
    {
        // 기본 구현 제공
    }
    
    // abstract: 구현 없음, 오버라이드 필수
    protected abstract void Initialize();  // 빨간 줄 안 나오려면 자식에서 구현!
}

public class GoldenBlock : BaseBlock
{
    // Move()는 안 써도 됨 (기본 구현 사용)
    // Initialize()는 반드시 구현해야 함
    protected override void Initialize() { }
}
```

## 📊 단계별 비교표

| 항목 | 0단계 (enum) | 1단계 (분리) | 2단계 (상속) |
|------|--------------|--------------|--------------|
| **코드 중복** | 적음 | 매우 많음 | 없음 |
| **확장성** | 어려움 | 보통 | 쉬움 |
| **유지보수** | 어려움 | 매우 어려움 | 쉬움 |
| **타입 안전성** | 보통 | 좋음 | 좋음 |
| **이해 난이도** | 쉬움 | 쉬움 | 보통 |
| **설계 난이도** | 쉬움 | 보통 | 어려움 |

**결론**: 초기 설계는 어렵지만, 장기적으로는 3단계가 최고!
